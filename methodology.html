Methodology and sources

How The Rack Report is built.

Everything on this site comes from public news feeds and a small hand-checked project list, processed by an open script you can read. Here is exactly what happens, and where it can go wrong.

1Collect

Google News RSS searches (U.S. edition) and optional Google Alerts feeds.

2Tag

Keyword rules assign a topic, places, states and companies to each headline.

3Detect

Headlines naming a site, a stage and a U.S. place become project candidates.

4Publish

JSON files are committed to GitHub and served by GitHub Pages.

Sources and refresh schedule

A GitHub Actions workflow runs every hour, at 17 minutes past the hour (GitHub can delay scheduled runs by a few minutes when it is busy). It runs scripts/fetch_news.py, which reads the searches listed in data/feeds.json: Google News RSS queries for data center announcements, construction, power, policy and regional news, all using the U.S. edition of Google News. Any Google Alerts RSS feeds added to that file are read too.

We store only the headline, the publisher name, the publication time and the link. Article text is never copied; every headline links to the original publisher through Google News. The recent feed keeps 90 days of headlines (up to 3,000), and project candidates are kept for 180 days. Every headline is also written to a permanent monthly archive in data/archive/ that is never trimmed; the Newsroom's Include archive switch and the Project Atlas search it.

U.S. only

A story is dropped when every place it names is outside the United States. Because many foreign stories name no place we recognize, the script also drops stories with clear foreign markers (for example "data centre" spelling, foreign currencies or country names) and stories from a short list of non-U.S. outlets. Stories that name no place at all are kept. This means a few foreign stories can slip through and a few U.S. ones can be dropped.

Topics, places and companies

  • Topics come from keyword rules in the script, checked in this order: Policy / Permits, Land Acquisition, Expansion, Construction, Operations, New Announcement, Deals / Investment, Power / Utility, AI Infrastructure. The first match becomes the headline's topic; anything else is General.
  • Places come from a gazetteer (scripts/gazetteer.json) of U.S. states, counties and cities plus foreign places used only for filtering. Each U.S. place carries coordinates and a state, which becomes the headline's two-letter state code.
  • Companies are matched by name and common aliases (for example AWS for Amazon). "Stargate" counts toward OpenAI, Oracle and SoftBank.
  • Figures such as "1.2 GW" or "$10 billion" are read from the headline. Capacity figures above 20 GW are ignored because they describe grid-wide totals, not single projects.

Curated and detected projects

Curated projects (rack-shaped pins on the Atlas) are entered by hand in data/projects.json from public reporting, with exact coordinates where known. Each one has a verified flag that stays false until it has been checked against current sources.

Detected projects (ring pins) are created automatically when a headline mentions a data center or campus, a stage (announced, under construction, operational or expansion) and a U.S. place. The pin is placed at the city, county or state named, so state-level pins are approximate. Detected projects are leads to check, not confirmed facts.

Known limitations

  • Keyword tagging misses context. A headline about a vote against a project can still be tagged as an announcement.
  • Places can be ambiguous (Georgia, Washington, Aurora). The gazetteer favors the U.S. meaning.
  • The same project often appears under several headlines, so detected pins can duplicate each other.
  • Google News results vary, and paywalled or regional outlets may be missing.
  • Counts and charts describe headlines, not the industry as a whole.

Report a wrong pin or headline

Open an issue on GitHub with the project name or headline, what is wrong and a source link. Corrections to curated projects go straight into data/projects.json; recurring tagging mistakes are fixed in the rules so they stay fixed on the next refresh.

Code

The whole site is static HTML, CSS and JavaScript with no build step. The map uses Leaflet and Leaflet.markercluster from unpkg and map tiles from OpenStreetMap, darkened with a CSS filter. Source: github.com/awigaikwad02/datacenter-watch.
